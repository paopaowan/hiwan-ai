# Architecture Proposals

Proposals describe possible architecture changes. They are not decisions.

Use `TEMPLATE.md` for new proposals.

Naming:

`YYYY-MM-DD-<short-slug>.md`

Lifecycle:

`DRAFT → IN_REVIEW → REVISED → DECIDED → IMPLEMENTED`

Possible terminal states include `DEFERRED`, `REJECTED`, and `SUPERSEDED`.

A proposal becomes an accepted architecture decision only after Richard records the decision in `DECISIONS.md`.
