## Gotchas

- Heredoc commands require an exact terminating `EOF`.
- Large copy/paste blocks should always be verified.
- `git status` showing `learning/` does not prove individual files exist.
- `gh auth login` can upload an SSH public key automatically.
- An older terminal session may still show bash even after zsh is configured.
- `.venv` should not be tracked.
- `uv.lock` should be committed.
- Terminal output should not be copied back into the shell as commands.
- `git ls-remote origin refs/heads/main` and `git rev-parse HEAD` verify local/remote commit equality.
- Force-pushing is appropriate only when the remote change is understood and explicitly intended.
- `python` is available as the project interpreter after `source .venv/bin/activate`; it is not assumed to be a global command.
- Prefer `uv` for Python dependency management; use pip when a tool specifically requires it.
- `docker info` verifies that the Docker Engine is actually reachable, not merely that the CLI is installed.
- Obsidian should use the existing Markdown knowledge structure rather than creating a disconnected duplicate knowledge base.
- Always verify that an intended file change actually appears in `git status` before committing and pushing.

## Decisions

- Local-first architecture.
- Agent/data separation.
- Markdown as the durable knowledge format.
- Python 3.13 as the initial Python version.
- Node.js/npm installed through Homebrew.
- Docker installed through Homebrew Cask.
- Obsidian installed as the human-facing Markdown knowledge tool.
- Learning records explicitly include failures, gotchas, decisions, and commands.
- Prefer one-shot setup commands followed by explicit verification.
- Keep GitHub private for the initial Hiwan AI OS repository.
- Do not install AI frameworks until the local AI runtime architecture is chosen.
