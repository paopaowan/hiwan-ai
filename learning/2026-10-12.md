# 2026-10-12

## Learned

- A full-text search returning some documents is not proof of retrieval relevance.
- **Relevance**, **source authority**, **evidence selection**, and **answer grounding** must be evaluated separately. A single lexical score should not encode all four concerns.
- A canonical decision document does not need to rank first in every raw retrieval query; its authority matters when selecting evidence for questions about approved decisions.
- Document-level retrieval can return irrelevant opening paragraphs. Section-level passages with concrete source locations provide more inspectable evidence.
- Synthetic unit tests alone are insufficient; realistic repository examples and live local-model tests caught problems that the tests missed.
- A real source path and line number prove that a referenced location exists, not that every factual claim in a generated answer is supported by it.
- Test assertions should check behavior and contracts rather than incidental prompt wording or exact fallback phrasing.
- A nonempty model answer can still be truncated. Generation completion must be checked.

## Understood

The minimum working Knowledge Layer now follows:

```text
Question
  -> Relevant Markdown passage retrieval
  -> Authority-aware evidence selection
  -> Selected source excerpts with paths and line ranges
  -> Local Qwen3.5 answer
  -> Application-verified evidence identifiers
```

- The first usable system need not have embeddings, a vector database, LangChain or MCP.
- Grounding is not fully solved by valid citation identifiers; semantic correctness still needs evaluation.
- Public project Markdown is the current test corpus. Real private/family data is not authorized for ingestion by this milestone.

## Failed

1. **Whole-document search:** The initial complete phrase matched only the Gemini review, missing more appropriate formal sources.
2. **Weighted lexical ranking:** Adding punctuation normalization and source bonuses helped the short query, but the full question later ranked `ARCHITECTURE.md` or the review above `DECISIONS.md`.
3. **Frequency-based ranking:** A longer Gemini review won by repeating the topic more often.
4. **Grounding mistake:** One Qwen response wrongly described `.gitignore` as if it enforced the primary privacy boundary.
5. **Compatibility tests:** After the redesign, two legacy unit tests failed because they asserted exact phrases in a prompt and fallback message. Updating those assertions produced 28 passing tests.
6. **Potential truncation:** A Qwen answer ended with `This boundary` before the completion guard was introduced.

## Gotchas

- Downloaded replacements were copied over earlier files before the suggested backup command. This did not itself corrupt the project; the new files ran and the remaining failures were identified by tests.
- A backup taken after overwriting a file only preserves the already-overwritten version, not the original.
- Keep a backup under `~/.hiwan/dev/cache/` before future replacement operations, and validate ZIP paths before extraction.
- Use `set -e` or an equivalent guard to stop on test failures.
- Avoid equating smoke-test `PASS` with a production-level security or semantic guarantee.
- Keep the pre-commit Gitleaks and `git diff --cached --check` gates.

## Decisions

- Keep the phased Knowledge Layer minimal and local-first.
- Keep retrieval relevance separate from source authority/evidence selection.
- Use section-level evidence with inspectable source locations.
- Let the application validate source references rather than trusting model-invented citations.
- Do not add embeddings, a vector database, or a larger RAG framework without measured need.
- Prioritize reliability and evaluation before expanding the knowledge corpus to private information.

## Questions

- How often does the system select an authoritative, relevant source across diverse real questions?
- Are returned cited passages sufficient to support the specific claims in each answer?
- What should happen if the LLM returns truncated, malformed, uncited, or contradictory text?
- How should conflicts between old reviews and current accepted decisions be flagged?
- How should text containing instructions inside Markdown documents be treated as untrusted data?
- What retrieval quality metrics justify upgrading from Python lexical retrieval to SQLite FTS5 or another engine?

## Next — Phase 2C: Reliability & Evaluation

2. Record expected evidence/source **roles** or required claims, not only a fixed first-ranked filename.
3. Add regression tests for `done_reason="length"`, empty answer, invalid citations and no relevant evidence.
4. Measure retrieval coverage and authority-aware evidence selection separately from model-answer correctness.
5. Inspect hallucinations, missing caveats, and contradictions with authoritative sources.
6. Keep all test questions and results synthetic or based on public, non-sensitive project files.

## Phase 2C — Final Reliability Review

### Evaluation

- Unit tests: 43 passed.
- Candidate source recall at top 5: 11/12 after chunking changes.
- Evidence selection source and section at top 3: 12/12.
- Local Qwen3.5 answered all 12 evaluation questions.
- Cumulative human semantic review: 12/12 after targeted retests.
- The final code was not used to rerun all 12 answers together.

### Failures and fixes

- P2C-05: Tool/MCP decision was missed; improved intent and evidence selection.
- P2C-11: Ranking and grounding failure notes were rejected by an overly strict relevance threshold.
- P2C-12: Gemini governance comments were missed; improved review selection and section granularity.
- Long Markdown sections hid answer-bearing text; introduced more focused passages.
- P2C-09: SQLite path existed in source and Markdown but was omitted from selected evidence. Location-aware evidence selection now supplies the exact path.
- P2C-01: Strengthened distinction between privacy design requirements and absolute security guarantees.
- P2C-06: Distinguished accepted Identity/Policy architecture from implemented Phase 1 capabilities.

### Lessons

- Retrieval relevance, source authority, and answer grounding are separate concerns.
- A valid source citation does not prove that the cited text supports every claim.
- Source-level retrieval success does not guarantee that the required fact reaches the model.
- Real answer evaluation must include semantic review, not just successful generation.
- Preserve concrete failures as regression cases before adding infrastructure.

### Next

- Keep the Phase 2C evaluation suite as a regression baseline.
- Avoid introducing a vector database until lexical retrieval limitations are demonstrated by new cases.
- Test reliability on new, previously unseen questions before expanding to private knowledge.
