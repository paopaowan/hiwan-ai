# 2026-10-17 — Public learning retrospective

**Scope:** sanitized retrospective on work discussed during October 14–17, 2026. It is **not** a verbatim daily terminal log, nor proof of the current deployed system. Private source-review details and family data are deliberately omitted.

## Learned

- An AI operating system needs a **development domain** as well as user-facing chat and administration. A platform should explain how it is changed, tested, reviewed, and recovered.
- **Local-first data** does not require local-only inference. Cloud models can improve interactive quality without owning durable private knowledge.
- A coding agent's **Git worktree is version isolation, not an OS security sandbox**. Independent execution permissions and synthetic-data tests are needed before accepting an isolation claim.
- A backup's upload and checksum do not prove recoverability. Clean-environment restore is a separate verification.
- Personal learning apps need an actual progression path, not only generic translation and note-taking tools.

## Built / recorded evidence

- The project established a more explicit division among Family Chat, Dev OS, and Admin OS at the architecture-planning level.
- A first encrypted **offsite Git-history snapshot** was created, uploaded, downloaded, and compared byte-for-byte, as reported by the local execution and confirmed by the existence of the private remote artifact. A clean-environment restore **has not yet been demonstrated**.
- A beginning-level **Angolan Portuguese (pt-AO)** learning application was scoped in two increments: local learning tools first, then validated regional pronunciation.
- The public repository documentation was refreshed to reflect these directions. This update does **not** publish the locally developed application code.

## Understood

- **Family Chat**: users need useful natural interaction, but it must not grant operational privileges.
- **Dev OS**: allow rapid coding and tests inside a properly isolated practice environment; reserve separate approval for activities with real financial, private-data, production-service, or public-release impact.
- **Admin OS**: operational privileges, deployment, backup, and restore must remain separately controlled.
- For the language app, a source-to-note pipeline can begin with scanned material, offline macOS OCR, structured local metadata, and a searchable knowledge corpus. Speech audio must carry locale and license provenance.

## Failed

- Public Git documentation fell behind ongoing local work. A private backup was not a substitute for updating the curated public learning and roadmap pages.
- An initial passphrase-based encryption check failed because a randomly generated encryption passphrase was not correctly supplied during decryption verification. The flow was revised, and a later encrypted archive passed upload/download byte comparison.
- Earlier implementation reviews exposed the importance of matching source manifests, test evidence, and actually running artifacts rather than equating an intended commit with a deployed version.

## Gotchas

- **Committed Git history** and **uncommitted working-tree changes** are different backup scopes; neither alone backs up private runtime databases.
- Automatic speech from a nearby Portuguese locale must not be mislabeled as authentic Angolan pronunciation.
- Provider-specific consent and cost controls must be implemented at the action boundary, not described only in UI copy.
- Updating a public Git branch while local branches are ahead creates an integration task. Always fetch and reconcile without force-pushing away local history.
- A review's or roadmap's claimed test count must not replace reproducible, version-stamped test output.

## Decisions (public summary)

- Continue publishing open software and non-sensitive learning records.
- Protect private and family data outside the public repository.
- Organize the next development effort around an isolated coding-agent workflow and a pt-AO learning application.
- Treat Hermes-style autonomous operation as a later, separately assessed capability.
- Keep ordinary isolated coding and testing lightweight; restrict high-impact actions using explicit approval and existing controls.
