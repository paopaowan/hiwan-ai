# 2026-10-07

## Learned

- Hiwan AI completed its first end-to-end local-first Agent tracer bullet.
- A design principle is not evidence until it survives an implementation test.
- Public software and private runtime data can be enforced by physical filesystem separation:
  - public repository: `~/hiwan-ai`
  - private runtime data: `~/.hiwan`
- `.gitignore` is useful as defense-in-depth, but it must not be the primary privacy boundary.
- Security tools themselves need positive-control validation.
- Gitleaks `8.30.1` produced a false negative against a synthetic GitHub PAT in the local environment.
- A pinned Gitleaks `8.18.4` correctly detected the synthetic PAT and was therefore selected as the trusted local scanner.
- A pre-commit security gate should fail closed when the trusted scanner is missing.
- Qwen3.5 27B MLX runs successfully through Ollama on the Mac mini using the MLX runner and 100% GPU.
- Thinking-enabled model behavior can consume a short `num_predict` budget before final content is emitted.
- `think: false` is appropriate for deterministic Phase 1 functional tests.
- A thin LLM client is enough to isolate the Agent from Ollama-specific HTTP details.
- The Agent can preserve the future `Identity -> Policy -> Tool -> Data` boundary without implementing a full authorization system.
- MCP is not required to prove the Tool abstraction.
- SQLite is sufficient for Phase 1 local persistence and can live outside the Git repository.
- The minimal architecture became useful only after the components were connected end-to-end.

## Understood

### Public Software / Private Runtime Data

The architecture is now implemented as:

```text
~/hiwan-ai/
= public software / architecture / tests

~/.hiwan/
= private runtime data
```

This is stronger than a Git-only protection model.

### Agent State

The Agent may hold transient execution state.

The Agent does not own durable user memory or durable user data.

### Identity / Policy

Phase 1 preserved:

```text
Identity -> Policy -> Tool -> Data
```

without implementing:

- RBAC
- ABAC
- delegation
- family permissions
- child identity
- consent engine

Current identity:

```text
richard
```

Current policy:

```text
minimal allow/deny
```

### Tool / MCP

The first Tool works without MCP.

Therefore:

```text
Tool != MCP
```

remains supported by implementation evidence.

### Runtime / Model

The Agent uses a thin runtime boundary and does not depend directly on Ollama HTTP details.

### Persistence

SQLite is enough for the current single-user tracer-bullet workload.

There is still no evidence requiring PostgreSQL or a Vector DB.

## Failed

### Gitleaks 8.30.1 False Negative

The scanner reported `no leaks found` for a synthetic GitHub PAT.

This proved that security tooling must be validated with positive controls.

### Qwen Thinking Budget

A functional test with:

```text
num_predict=32
```

and thinking enabled consumed the output budget inside the thinking channel.

Result:

```text
Response: ''
Done reason: length
```

The fix for deterministic functional tests was:

```text
think: false
```

### Downloaded Python Files Landed in Wrong Directory

Several downloaded files landed in the repository root instead of their intended package directory.

Examples:

```text
__init__.py
llm.py
agent.py
```

This caused `ModuleNotFoundError` until the files were moved into:

```text
hiwan_ai/
```

### Python Test Import Path

`uv run pytest` did not automatically make the repository root importable in the current setup.

The successful command was:

```text
PYTHONPATH=. uv run pytest -q
```

This remains a temporary Phase 1 execution detail rather than a reason to introduce packaging complexity immediately.

## Gotchas

- Never trust a security scanner solely because it says `no leaks found`.
- Use a positive-control secret test before relying on a scanner as a gate.
- Keep the trusted scanner version pinned independently from Homebrew upgrades.
- `.git/hooks/` is local and is not committed to Git.
- Private runtime data should never depend on `.gitignore` for primary protection.
- Downloaded artifact filenames and destination directories must be verified before testing.
- `uv run pytest` and `uv run python` may not have identical import behavior in an uninstalled source tree.
- Thinking models may consume token budgets differently from non-thinking models.
- A model being resident does not mean a deterministic output test has passed.
- End-to-end success does not mean production reliability has been proven.

## Decisions

- Keep `~/.hiwan/` as the physical private runtime root.
- Keep `~/.hiwan/dev/` as the default Phase 1 environment.
- Keep real private data separate under `~/.hiwan/private/`.
- Use pinned Gitleaks `8.18.4` as the currently trusted local pre-commit scanner.
- Use Ollama + `qwen3.5:27b-mlx` as the Phase 1 local inference baseline.
- Use 8192 tokens as the current baseline context for ordinary Phase 1 tests.
- Keep the LLM abstraction thin.
- Keep Identity and Policy as minimal boundaries rather than full systems.
- Treat Tool as an architecture concept independent of MCP.
- Use SQLite for current Phase 1 persistence.
- Do not introduce PostgreSQL or a dedicated Vector DB without evidence.
- Do not add a large Agent framework.
- Stop expanding architecture during Phase 1H unless implementation evidence requires it.
